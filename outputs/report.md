# 드론 예측정비 분석 보고서

> 모든 숫자는 `drone_pm.py` 실행 결과이며, 괄호 안에 출처 파일을 적었다. 교육용 가상 데이터.

## 1. 데이터 처리 기준과 근거 (outputs/eda_summary.txt, outputs/cleaning_log.csv)

| 대상 | 판단 | 처리 | 건수 |
|---|---|---|---|
| downtime_hours = 999 | 다른 최댓값과 동떨어진 결측 코드(입력 실수) | 값을 지어내지 않고 '모름'(빈 값)으로 둠, `downtime_missing` 표시. 로지스틱회귀만 모델 안에서 학습 데이터 중앙값으로 채움(트리 모델은 빈 값 그대로 학습) | 4 |
| maintenance_cost ≥ 10,000이면서 100의 배수 | 100배 단위 오입력. 정상 최댓값 611과 15,000 사이에 값이 없고, 나머지 중 100의 배수는 100·200·300뿐. ÷100 하면 150~190으로 사후정비 정상 범위이며 수리시간·부품 수로 본 예상 비용과 맞음 | ÷100, `cost_fixed` 표시 | 5 |
| fault_code·fault_category 결측 | 모두 예방정비 → 고장이 없어 원래 값 없음 | '없음' 범주 | 학습 1,707 / 시험 876 / 이번 달 62 |
| days_since_last_maintenance 결측 (+ 여기서 계산하는 hours_per_day_recent) | 드론별 첫 기록 → 직전 정비 없음 (이유가 있는 결측) | 비워 두고 `is_first_maintenance = 1` 표시. 0으로 채우지 않음(0은 '방금 정비함'), 중앙값으로 채우지 않음('51일 전 정비'가 됨) | 150 |
| days_since_last_pm · hours_since_last_pm 결측 | 예방정비 이력 없음 (이유가 있는 결측) | 비워 둠. 0으로 채우지 않음 | 1 |

빈 값은 트리 모델(랜덤포레스트 · 그래디언트부스팅)이 그대로 학습한다. 빈 값을 다루지 못하는 로지스틱회귀만 모델 안에서 학습 데이터 중앙값으로 채운다(검증 · 시험 값은 쓰지 않음). 직전 정비 없는 기록은 학습 데이터(2023-01~03)에만 있고 시험 · 이번 달에는 없다.

| availability_rate ≤ 0.3 | 정비 뒤 고장이 반영된 값(재고장률 100%) | 컬럼 자체를 제외 | - |

**삭제한 행은 없다.** 이상치는 값만 고치고 표시 컬럼으로 남겨 추적할 수 있게 했다.

**반복 고장 드론 DR-0034**: 기록 52건(드론 중앙값 22건), 정비 간격 중앙값 7일, 학습 재고장률 80%(전체 22%). 날짜·비행시간이 일관되어 입력 오류가 아닌 실제 반복 고장 기체로 판단해 지우지 않았다.

**반복 고장 드론 DR-0115**: 기록 151건(드론 중앙값 22건), 정비 간격 중앙값 4일, 학습 재고장률 96%(전체 22%). 날짜·비행시간이 일관되어 입력 오류가 아닌 실제 반복 고장 기체로 판단해 지우지 않았다.

## 2. 넣지 않은 컬럼과 이유

| 컬럼 | 이유 |
|---|---|
| availability_rate | '그 달' 가동률이라 정비 뒤 같은 달의 고장·중단이 섞임(<=0.3이면 재고장률 100%). 정비 직후에는 알 수 없고 이번 달 파일에도 없음 |
| failure_within_30days | 예측 대상(정답) |
| fault_code | 약 40종으로 잘게 나뉘어 학습 건수가 적음. 같은 정보를 fault_category로 사용 |
| equipment_id | 식별자. 드론 고유 성향은 과거 이력 피처로 반영 |
| maintenance_date | 날짜 자체 대신 계절(월 sin/cos)과 경과일 피처로 사용 |
| cost_fixed | 데이터 처리 표시용(입력 오류 여부는 재고장과 무관) |

사용 피처 32개: 범주 ['equipment_type', 'unit_code', 'maintenance_type', 'fault_category', 'prev_maintenance_type'], 수치 27개(과거 이력 피처 포함). 이력 피처는 train → test → this_month 기록을 드론별로 이어 붙여 그 정비일까지의 기록만으로 계산했다.

## 4. 위험 표시 기준 (outputs/threshold_costs.csv, 검증 기간에서만 결정)

비용 = 놓친 재고장 수 × 놓침 비용 + 기준 이상 건수 × 60만원

| 놓침 비용 | 기준 확률 | 표시 건수 | 잡은 재고장 | 놓친 재고장 | 총비용(만원) |
|---|---|---|---|---|---|
| 300만원 | 0.22 | 254 | 149 | 27 | 23,340 |
| 600만원 | 0.11 | 354 | 162 | 14 | 29,640 |

참고: 아무것도 점검하지 않으면 52,800만원(300) / 105,600만원(600), 전부 점검하면 38,580만원. 놓침 비용이 커지면 기준이 낮아져 더 많이 점검하는 쪽이 유리해진다.
