# 드론 예측정비 분석 보고서

> 모든 숫자는 `drone_pm.py` 실행 결과이며, 괄호 안에 출처 파일을 적었다. 교육용 가상 데이터. 재점검 계획은 별도 문서 `outputs/recheck_plan_2026_01.md`.

## 요약

- **목적**: 정비를 마친 드론 중 30일 안에 다시 고장 날 드론을 골라 2026-01 재점검 20대를 정한다.
- **모델**: 랜덤포레스트. 검증(2024-07~12) PR-AUC **0.799** (95% 구간 0.743~0.848), 경과연수순 0.348 · 무작위 0.280.
- **월 20대 적중**: 6개월 합 **39건** / 가능한 최대 56건 (경과연수순 18.34건, 무작위 13.56건).
- **위험 표시 기준**: 확률 **0.22** 이상 (놓침 600만원이면 0.11).
- **주의**: 반복 고장 드론(DR-0034, DR-0115)을 빼면 PR-AUC가 0.612로 내려간다. 그래도 기준선보다 높다.

| 용어 | 뜻 |
|---|---|
| 재고장 | 정비 뒤 30일 안에 사후 · 긴급정비가 있었음 (`failure_within_30days` = 1) |

## 3. 피처 만들기

학습 → 시험 → 이번 달 기록을 드론별로 이어 붙여, **그 정비일까지의 기록만으로** 계산했다. 그 뒤 기록을 지우고 다시 계산해도 같은 값인지 `reports/verify_results.py`(V4)로 확인했다.

| 피처 | 뜻 | 왜 |
|---|---|---|
| 최근 30일 고장 수 (`fail_cnt_30d`) | 이번 정비 포함 최근 30일 사후 · 긴급정비 수 | 고장이 몰려 있으면 곧 또 고장 날 가능성이 큼 (README 예시: 최근 기간 고장 수) |
| 최근 90일 고장 수 (`fail_cnt_90d`) | 최근 90일 고장 수 | 30일보다 긴 흐름 |
| 최근 180일 고장 수 (`fail_cnt_180d`) | 최근 180일 고장 수 | 반기 흐름 |
| 최근 1년 고장 수 (`fail_cnt_365d`) | 최근 1년 고장 수 | 기체의 장기 고장 성향 |
| 최근 90일 정비 횟수 (`maint_cnt_90d`) | 최근 90일 정비 횟수(종류 무관) | 정비가 잦은 기체 |
| 1년 내 같은 유형 고장 수 (`same_cat_fail_365d`) | 이번 고장과 같은 유형의 1년 내 고장 수 | 같은 계통 반복 고장 = 근본 원인 미해결 신호 |
| 최근 180일 정비 실패 수 (`unsuccess_cnt_180d`) | 최근 180일 정비 실패 수 | 정비가 잘 안 된 기체 |
| 최근 180일 심각도 합 (`severity_sum_180d`) | 최근 180일 고장 심각도 합 | 고장 건수에 심각도를 더한 부담 |
| 직전 고장 뒤 경과일 (`days_since_prev_failure`) | 직전 고장(이번 제외) 뒤 경과일, 고장 이력 없으면 730 | 고장 간격이 짧을수록 위험 (README 예시: 직전 고장 뒤 경과일) |
| 예방정비 뒤 경과일 (`days_since_last_pm`) | 마지막 예방정비 뒤 경과일 | 예방정비 주기가 밀리면 위험 |
| 예방정비 뒤 비행시간 (`hours_since_last_pm`) | 마지막 예방정비 뒤 비행시간 | README 예시: 예방정비 뒤 비행시간 |
| 과거 정비 기록 수 (`n_prior_records`) | 과거 정비 기록 수 | 기체의 누적 정비 이력 |
| 최근 하루 비행시간 (`hours_per_day_recent`) | 직전 정비 뒤 하루 평균 비행시간 | 많이 쓰는 기체는 빨리 닳음 |
| 직전 정비 구분 (`prev_maintenance_type`) | 직전 정비 구분 | 고장정비가 연속되는지 |
| 이번 정비가 고장정비 (`is_failure`) | 이번 정비가 사후 · 긴급정비인지 | 고장정비 뒤 재고장률이 높음 (1장) |
| 정비 월(계절) (`month_sin`, `month_cos`) | 정비 월(계절) — sin · cos 두 개로 표현 | 계절별 재고장률 차이 (1장). 12월과 1월이 가깝게 표현됨 |

- **반복 고장 드론**(DR-0034, DR-0115)은 재고장이 너무 잦아 맞히기 쉽다. 빼면 PR-AUC가 0.612로 내려가지만 경과연수순(0.264) · 무작위(0.216)보다 높다. 월 20대 적중은 드론당 1건으로 세므로 영향이 작다.

## 6. 위험 표시 기준 (outputs/threshold_costs.csv, 검증 기간에서만 결정)

비용 = 놓친 재고장 수 × 놓침 비용 + 기준 이상 건수 × 60만원. 확률 0.01~0.99를 0.01 간격으로 모두 계산해 가장 싼 기준을 골랐다.

| 놓침 비용 | 기준 확률 | 표시 건수 | 잡은 재고장 | 놓친 재고장 | 총비용(만원) | 이론값 |
|---|---|---|---|---|---|---|
| 300만원 | 0.22 | 254 | 149 | 27 | 23,340 | 0.20 |
| 600만원 | 0.11 | 354 | 162 | 14 | 29,640 | 0.10 |

- **이론값**: 확률이 정확하다면 '점검비 < 확률 × 놓침 비용'일 때 점검하는 게 이득이므로 기준은 점검비 ÷ 놓침 비용 = 60/300 = 0.20, 60/600 = 0.10이다. 실제로 고른 기준(0.22 · 0.11)은 이론값과 가까워, 모델의 확률이 크게 치우치지 않았다는 근거도 된다.
- 놓침 비용이 300 → 600만원으로 커지면 기준이 0.22 → 0.11로 낮아져 더 많이 점검한다 (표시 254 → 354건).
- 참고: 아무것도 점검하지 않으면 52,800만원(300) / 105,600만원(600), 전부 점검하면 38,580만원.
